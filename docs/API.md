# API конструктора форм etu-forms

Создание форм (вручную или с помощью ИИ), управление их публикацией, прием ответов от
неавторизованных пользователей, поиск ответов фильтрами, выгрузка ответов в XLSX.

Работать с ним можно из любого клиента, который умеет отправлять HTTP-запросы:
всё общение идёт по JSON, авторизация — одним заголовком.

## 1. Общие сведения

| Параметр       | Значение                                                        |
| -------------- | --------------------------------------------------------------- |
| Адрес сервера  | `http://localhost:3000` в разработке                            |
| Префикс        | `/api`                                                          |
| Формат запроса | `application/json`                                              |
| Формат ответа  | `application/json`, кроме скачивания файла — там бинарный поток |
| Даты           | ISO 8601 в UTC: `2026-08-16T12:34:56.789Z`                      |
| Идентификаторы | UUID версии 4                                                   |
| CORS           | разрешён один источник, cookie и учётные данные не передаются   |
| HTTPS          | терминируется обратным прокси перед приложением                 |

Все даты и в запросах, и в ответах — строки ISO 8601. В запросах достаточно
любой строки, которую однозначно понимает `Date`: и `2026-09-01`, и
`2026-09-01T09:00:00Z` подойдут.

Есть один служебный адрес вне префикса — `GET /health`. Он отвечает мгновенно
и не ходит ни в базу, ни в очередь, поэтому годится для проверки живости
процесса, но не для проверки зависимостей.

### Ограничение частоты запросов

Весь `/api` закрыт лимитами. Окно везде — одна минута, каждый ответ несёт
заголовки `RateLimit` и `RateLimit-Policy`, а при отказе — ещё и `Retry-After`.

| Что                                        | Лимит | Считается по       |
| ------------------------------------------ | ----- | ------------------ |
| Весь `/api`                                | 600   | адресу клиента     |
| `POST /api/auth/login`                     | 5     | адресу клиента     |
| Заполнение формы                           | 120   | токену либо адресу |
| `POST /api/forms/:formId/responses/export` | 10    | владельцу токена   |

Отдельные лимиты не заменяют общий, а складываются с ним: сохранение черновика
расходует и свои 120, и общие 600. Такой ответ несёт по два заголовка
`RateLimit` и `RateLimit-Policy` — по одному на каждый счётчик; клиент,
читающий их через `headers.get`, получит оба значения через запятую.

«Заполнение формы» — это три запроса респондента с общим счётчиком на всех:

```
POST  /api/forms/:formId/responses
GET   /api/forms/:formId/responses/:id
PATCH /api/forms/:formId/responses/:id
```

Отдельная строка им нужна из-за автосохранения: форма шлёт `PATCH` примерно раз
в секунду, пока её заполняют. Отправка (`POST .../submit`) в эту строку не
входит — она случается один раз и живёт под общими 600.

Респондент обычно аноним, поэтому считается по адресу; если токен всё же
предъявлен, счётчик привязывается к нему — иначе один офисный адрес делили бы
все сотрудники. Экспорт ставит в очередь тяжёлую задачу и доступен только по
токену, поэтому у него владелец токена и никакого запасного варианта.

Лимиты живут в памяти процесса. Их счётчики не переживают перезапуск и не
делятся между экземплярами приложения.

### Заголовки безопасности

Приложение отдаёт стандартный набор заголовков (`helmet`): `nosniff`,
`Referrer-Policy`, `Strict-Transport-Security`, `X-Frame-Options`,
`Content-Security-Policy`. Заголовка `X-Powered-By` нет.
`Cross-Origin-Resource-Policy` намеренно ослаблен до `cross-origin` — API
живёт на другом источнике, чем клиент.

## 2. Аутентификация

Аутентификация построена на одном механизме — bearer-токене. Неважно, получили
вы его входом по паролю или выпустили вручную для интеграции: проверяются оба
одинаково.

Путь от нуля до первого запроса:

```
1. POST /api/auth/login          { email, password }
   ← 200 { id, name, token, expiresAt }         ← токен показывается один раз

2. Во все последующие запросы:
   Authorization: Bearer <token>

3. GET /api/auth/me              проверить, что токен жив, и узнать, чей он
   ← 200 { id, email, createdAt }

4. (по желанию) POST /api/tokens  { name }      ← долгоживущий токен для интеграции
5. DELETE /api/tokens/:id                        ← отозвать любой свой токен
```

Что стоит знать заранее:

- **Токен возвращается ровно один раз** — в ответе на вход или на выпуск.
  Сохраните его сразу: на сервере хранится только необратимый хеш, показать
  секрет повторно невозможно.
- **Email нечувствителен к регистру.** При входе система сама приводит адрес к
  нижнему регистру, так что `Ivan@Example.com` и `ivan@example.com` — один и
  тот же пользователь.
- **Регистрации через API нет.** Пользователи заводятся администратором.
- **Отдельного выхода тоже нет.** Чтобы завершить сессию, удалите её токен
  через `DELETE /api/tokens/:id`.

## 3. Жизненный цикл токенов

| Этап       | Что происходит                                                             |
| ---------- | -------------------------------------------------------------------------- |
| Выпуск     | Вход по паролю или запрос `POST /api/tokens`                               |
| Вид        | 43 символа из набора `[A-Za-z0-9_-]`                                       |
| Хранение   | На сервере лежит только SHA-256 от токена, сам секрет нигде не сохраняется |
| Показ      | Один раз — в ответе на выпуск                                              |
| Имя        | У сессионного проставляется автоматически: `Session Token (<дата>)`        |
| Срок жизни | Сессионный — 24 часа; выпущенный вручную живёт столько, сколько вы указали |
| Проверка   | Срок сверяется на каждом запросе                                           |
| Отзыв      | `DELETE /api/tokens/:id` — действует немедленно                            |
| Каскад     | Вместе с пользователем удаляются все его токены                            |

**Два вида токенов.** Сессионный выдаётся входом по паролю и живёт сутки.
Персональный вы выпускаете сами — для CI, скриптов и серверных интеграций;
без указанного срока он бессрочен. Технически они устроены одинаково, но в
списке `GET /api/tokens` показываются только персональные: сессия исчезнет
сама, когда истечёт её срок.

Просроченный, отозванный и никогда не существовавший токен отвечают одинаково —
`401` с сообщением `Invalid, expired or revoked API token`. По ответу нельзя
понять, какой из трёх случаев произошёл.

## 4. Аутентификация по API-токенам

Долгоживущий токен для интеграции создаётся так:

```http
POST /api/tokens HTTP/1.1
Authorization: Bearer <любой ваш действующий токен>
Content-Type: application/json

{ "name": "CI pipeline" }
```

- Срок жизни задаётся необязательным полем `expiresAt`: передайте дату, `null`
  или не передавайте ничего — во втором и третьем случае токен бессрочен.
- Токен всегда принадлежит тому, от чьего имени сделан запрос. Выпустить ключ
  «за другого пользователя» нельзя.
- Прав внутри токена нет: любой действующий токен открывает все ресурсы своего
  владельца и только их.

Передаётся токен единственным способом — заголовком:

```
Authorization: Bearer <token>
```

Заголовок разбирается строго: он должен начинаться со слова `Bearer` с большой
буквы и пробела. Ни query-параметры, ни cookie, ни `X-Api-Key` не поддерживаются.

## 5. Права доступа

Ролей в системе нет — всё решает владение ресурсом. Работают два механизма.

**Ограничение выборки.** В списках вы физически не увидите чужих строк: они
отсекаются ещё в запросе к базе, поэтому не попадают ни в `data`, ни в счётчик
`meta.total`.

| Список                             | Что попадает в выдачу                        |
| ---------------------------------- | -------------------------------------------- |
| `GET /api/forms`                   | только ваши формы                            |
| `GET /api/tokens`                  | только ваши персональные токены              |
| `GET /api/forms/:formId/responses` | ответы этой формы — и только если форма ваша |
| `GET /api/jobs`                    | только ваши фоновые задачи                   |

**Проверка прав на конкретном объекте.** Применяется при чтении одного объекта,
изменении, удалении и в действиях вроде публикации или запуска экспорта.

| Объект | Кто может читать                                  | Кто может изменять и удалять |
| ------ | ------------------------------------------------- | ---------------------------- |
| Форма  | все, если она опубликована; иначе только владелец | только владелец              |
| Ответ  | зависит от того, отправлен ли он (см. ниже)       | так же, как чтение           |
| Токен  | только владелец                                   | только владелец              |
| Задача | только владелец                                   | только владелец              |

Как отличать коды ответа:

- **401** — вы не представились, а без имени доступа нет;
- **403** — вы представились, но объект чужой;
- **404** — объекта нет вовсе.

Форма считается публичной, когда дата публикации уже наступила, а дата
архивации ещё нет. Управляют этим четыре перехода — публикация, снятие с
публикации, архивация и возврат из архива. Они же переключают доступ ко всей
ветке формы, включая приём ответов; подробности — в разделе
[Жизненный цикл формы](#жизненный-цикл-формы-lifecycle).

### Доступ к отдельному ответу

Ответы живут по своим правилам, и это осознанное решение. Респондент заполняет
форму анонимно, но на фронтенде есть сохранение черновика — значит он должен
уметь вернуться к незаконченному ответу, не заводя аккаунта.

Поэтому **пока ответ не отправлен, ключом к нему служит его идентификатор**:
ссылку с ним можно открыть без всякого токена. Как только ответ отправлен,
доступ к нему остаётся только у автора формы — отправка необратима и для
респондента односторонняя.

| Кто                 | Черновик, форма опубликована | Черновик, форма закрыта | Отправленный ответ |
| ------------------- | ---------------------------- | ----------------------- | ------------------ |
| Аноним              | доступ есть                  | 401                     | 401                |
| Автор формы         | доступ есть                  | доступ есть             | доступ есть        |
| Другой пользователь | доступ есть                  | 403                     | 403                |

Отсюда два следствия:

- идентификатор формы секретом не является — он лежит в ссылке на заполнение.
  Секретен только идентификатор ответа, это случайный UUID со 122 битами
  энтропии;
- сводка по всем ответам под эту модель не подпадает: список
  `GET /api/forms/:formId/responses` требует токен и отдаёт только ответы ваших
  форм.

## 6. Цепочка промежуточных обработчиков

Каждый запрос проходит через одну и ту же цепочку. Знать её полезно, чтобы
понимать, откуда взялся тот или иной ответ.

```
заголовки безопасности → CORS → разбор JSON → общий лимит частоты
                                                      ↓
                          отдельный лимит → аутентификация → валидация → обработчик
                                                                            ↓
                                                        обработчик ошибок / 404
```

| Шаг                    | Что делает                                                              |
| ---------------------- | ----------------------------------------------------------------------- |
| Заголовки безопасности | Ставит набор `helmet` и убирает `X-Powered-By`                          |
| CORS                   | Пропускает запросы с единственного разрешённого источника               |
| Разбор JSON            | Читает тело запроса; на битом JSON отвечает `400`                       |
| Общий лимит частоты    | 600 запросов в минуту с одного адреса на весь `/api`                    |
| Отдельный лимит        | Есть у входа по паролю, черновика ответа и экспорта — см. раздел 1      |
| Аутентификация         | Обязательная — требует действующий токен; мягкая — пропускает и анонима |
| Валидация              | Проверяет тело и query-строку по схеме метода                           |
| Обработчик             | Выполняет саму операцию                                                 |
| Обработчик ошибок      | Приводит любую ошибку к единому JSON-формату                            |

Порядок двух средних шагов зависит от метода: у экспорта лимит стоит после
аутентификации, потому что считается по владельцу токена, а не по адресу.

Про валидацию стоит знать три вещи:

- **Неизвестные поля отбрасываются молча.** Они не попадут ни в базу, ни в
  текст ошибки. Так, например, `userId` в теле создания формы будет
  проигнорирован — владелец всегда берётся из токена.
- **Пустое тело — ошибка.** Если после разбора не осталось ни одного известного
  поля, вернётся `400` с пояснением, что тело пустое. К query-строке это
  правило не относится: список без параметров — нормальный запрос.
- **Query-параметры проверяются так же строго, как тело.** Неверный номер
  страницы или неизвестное значение фильтра дадут `400`, а не пустую выдачу и
  не ошибку сервера.

Отдельная деталь: **мягкая аутентификация** пропускает запрос без заголовка, но
не прощает испорченный токен. Если заголовок есть и он неверный — будет `401`,
даже если метод в принципе открыт анониму.

## 7. Пагинация

Постраничный вывод устроен одинаково во всех списках и управляется двумя
параметрами.

| Параметр | Тип   | По умолчанию | Допустимые значения      |
| -------- | ----- | ------------ | ------------------------ |
| `page`   | целое | `1`          | больше нуля              |
| `limit`  | целое | `20`         | от 1 до 100 включительно |

Значения приходят строками и приводятся к числам автоматически. Всё, что не
приводится или выходит за границы, — ошибка `400`, а не молчаливое усечение.

Ответ всегда одной формы: сами объекты в `data`, счётчики в `meta`.

```json
{
  "data": [],
  "meta": {
    "total": 137,
    "page": 2,
    "limit": 20,
    "totalPages": 7
  }
}
```

`total` считается с теми же ограничениями и фильтрами, что и сама выборка,
поэтому он всегда согласован с содержимым страницы и никогда не «протекает» за
границы ваших данных.

Постраничный вывод есть у четырёх списков: токены, формы, ответы на форму и
фоновые задачи.

## 8. Фильтрация и сортировка

Фильтры складываются друг с другом по «и»: чем больше параметров, тем уже
выдача. Значения всегда передаются как параметры запроса к базе, поэтому
спецсимволы в поисковой строке безопасны.

### Формы

| Параметр      | Тип             | Что делает                                    |
| ------------- | --------------- | --------------------------------------------- |
| `title`       | строка          | Поиск подстроки в названии без учёта регистра |
| `status`      | одно из четырёх | Отбор по текущему статусу формы               |
| `createdFrom` | дата            | Созданные не раньше указанного момента        |
| `createdTo`   | дата            | Созданные не позже указанного момента         |

`status` принимает `draft`, `scheduled`, `published` и `archived`. Статус
вычисляется на момент запроса, поэтому форма с публикацией «на завтра» найдётся
по `scheduled` сегодня и по `published` — завтра.

### Ответы на форму

| Параметр         | Тип                 | Что делает                                            |
| ---------------- | ------------------- | ----------------------------------------------------- |
| `answer[<поле>]` | строка              | Поиск подстроки в ответе на конкретное поле формы     |
| `answered`       | имя поля или массив | Оставить ответы, где заполнены все перечисленные поля |
| `submitted`      | `true`              | Только отправленные ответы                            |
| `submittedFrom`  | дата                | Отправленные не раньше указанного момента             |
| `submittedTo`    | дата                | Отправленные не позже указанного момента              |
| `formId`         | UUID                | Дополнительное сужение по форме                       |

Поиск по ответам — самый частый сценарий: он ищет подстроку без учёта регистра
в конкретном поле схемы.

```
GET /api/forms/{formId}/responses?answer[full_name]=Иван&answer[city]=Москва
```

Условия складываются, так что запрос выше найдёт ответы, где в имени есть
«Иван» **и** в городе есть «Москва».

Параметр `answered` принимает как одно имя, так и список — и требует, чтобы
были заполнены все перечисленные поля:

```
GET /api/forms/{formId}/responses?answered[]=email&answered[]=phone
```

### Фоновые задачи

| Параметр      | Тип    | Что делает                              |
| ------------- | ------ | --------------------------------------- |
| `status`      | статус | Отбор по состоянию задачи               |
| `type`        | строка | Отбор по типу операции                  |
| `formId`      | UUID   | Задачи, запущенные для конкретной формы |
| `createdFrom` | дата   | Созданные не раньше указанного момента  |
| `createdTo`   | дата   | Созданные не позже указанного момента   |

У списка токенов фильтров нет — только страница и размер страницы.

### Сортировка

Сортировка фиксирована: везде сначала идёт самое новое, то есть по убыванию
даты создания. Параметров вроде `sort` или `order` API не принимает.

## 9. Формат ответов об ошибках

Основной формат один и тот же для всех ошибок — код, сообщение и, если есть
что уточнить, подробности:

```json
{
  "code": "NOT_FOUND",
  "message": "Resource not found"
}
```

| Код                      | HTTP | Когда приходит                               |
| ------------------------ | ---- | -------------------------------------------- |
| `BAD_REQUEST`            | 400  | Запрос не прошёл проверку                    |
| `UNAUTHORIZED`           | 401  | Не представились, а метод требует прав       |
| `FORBIDDEN`              | 403  | Объект принадлежит другому пользователю      |
| `NOT_FOUND`              | 404  | Объекта или адреса не существует             |
| `PAYLOAD_TOO_LARGE`      | 413  | Тело запроса слишком велико                  |
| `UNSUPPORTED_MEDIA_TYPE` | 415  | Тело пришло не в JSON                        |
| `TOO_MANY_REQUESTS`      | 429  | Исчерпан лимит частоты запросов или квота ИИ |
| `SERVICE_UNAVAILABLE`    | 503  | Недоступна очередь задач или ИИ-сервис       |
| `INTERNAL_SERVER_ERROR`  | 500  | Непредвиденный сбой                          |

В отладочном режиме к ответу добавляется поле `stack` — в рабочей среде его нет,
а текст ошибки `500` заменяется на нейтральный.

### Ошибки проверки данных

Все проблемы с телом или query-строкой приходят с кодом `BAD_REQUEST` и
сообщением `Validation failed`. Конкретика — в поле `details`.

```json
{
  "code": "BAD_REQUEST",
  "message": "Validation failed",
  "details": [
    {
      "expected": "string",
      "code": "invalid_type",
      "path": ["title"],
      "message": "Invalid input: expected string, received undefined"
    }
  ]
}
```

`path` — путь до поля. Для вложенных структур он получается длинным, например
`["schema", "pages", 0, "elements", 1, "name"]`: ошибка во втором элементе
первой страницы схемы.

Пустое тело — частный случай:

```json
{
  "code": "BAD_REQUEST",
  "message": "Validation failed",
  "details": [
    {
      "code": "custom",
      "message": "The request body is empty or does not contain any fields allowed for this operation"
    }
  ]
}
```

Ответы респондентов проверяются ещё и на соответствие схеме формы. Формат тот
же, но каждая запись в `details` называет поле формы и человекочитаемую
причину:

```json
{
  "code": "BAD_REQUEST",
  "message": "Validation failed",
  "details": [{ "field": "full_name", "message": "This field is required" }]
}
```

### Два исключения из общего формата

**Ошибки токена** приходят коротким телом без кода — их формирует слой
аутентификации, до общего обработчика они не доходят:

```json
{ "message": "Invalid, expired or revoked API token" }
```

| Ситуация                                       | Сообщение                                 |
| ---------------------------------------------- | ----------------------------------------- |
| Нет заголовка или он не начинается с `Bearer ` | `Missing or invalid authorization header` |
| После `Bearer` пусто, метод требует прав       | `Token not provided`                      |
| После `Bearer` пусто, метод открыт анониму     | `Malformed authorization header`          |
| Токен не найден, просрочен или отозван         | `Invalid, expired or revoked API token`   |

Отказ по правам выглядит иначе — это обычный ответ основного формата
`{ "code": "UNAUTHORIZED", "message": "Authentication error" }`.

**Превышение лимита частоты** приходит в основном формате
(`{ "code": "TOO_MANY_REQUESTS", "message": "Too many requests" }`) вместе с
заголовками `RateLimit`, `RateLimit-Policy` и `Retry-After`. Суточный лимит ИИ
устроен так же, но с подробностями в `details`.

### Коды состояния

| Код | Когда возникает                                                                      |
| --- | ------------------------------------------------------------------------------------ |
| 200 | Чтение, изменение, переход статуса, генерация схемы, отмена задачи, скачивание файла |
| 201 | Создан объект: токен, форма, ответ                                                   |
| 202 | Задача принята в очередь                                                             |
| 204 | Объект удалён, тело ответа пустое                                                    |
| 400 | Не прошла проверка данных, недопустимый переход статуса, отмена завершённой задачи   |
| 401 | Нет действующего токена либо доступ закрыт для анонима                               |
| 403 | Объект принадлежит другому пользователю                                              |
| 404 | Нет такого адреса или объекта                                                        |
| 429 | Исчерпан лимит частоты запросов или суточная квота ИИ                                |
| 500 | Непредвиденный сбой                                                                  |
| 503 | Недоступна очередь фоновых задач или ИИ-сервис                                       |

## 10. Стандартные структуры ответов

### 10.1. Страница списка

```json
{ "data": [], "meta": { "total": 0, "page": 1, "limit": 20, "totalPages": 0 } }
```

### 10.2. Пользователь (User)

Пароль не возвращается никогда и ни в каком виде.

```json
{
  "id": "8f14e45f-ceea-467a-9c31-2b1b5f9dfc02",
  "email": "user@example.com",
  "createdAt": "2026-07-25T10:02:25.000Z"
}
```

### 10.3. Токен (ApiToken)

Ни владелец, ни вид токена, ни хранимый хеш наружу не отдаются.

```json
{
  "id": "0f0e3a35-9a8a-4d21-9b6a-9f7f1c0b3a10",
  "name": "Session Token (16.08.2026)",
  "expiresAt": "2026-08-17T18:00:00.000Z",
  "createdAt": "2026-08-16T18:00:00.000Z"
}
```

**Момент выпуска** — единственный ответ, где есть поле `token`. Так выглядит
результат входа и создания токена:

```json
{
  "id": "0f0e3a35-9a8a-4d21-9b6a-9f7f1c0b3a10",
  "name": "Session Token (16.08.2026)",
  "expiresAt": "2026-08-17T18:00:00.000Z",
  "createdAt": "2026-08-16T18:00:00.000Z",
  "token": "vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q"
}
```

### 10.4. Форма (Form)

```json
{
  "id": "3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b",
  "userId": "8f14e45f-ceea-467a-9c31-2b1b5f9dfc02",
  "title": "Анкета участника",
  "schema": { "pages": [] },
  "settings": {},
  "status": "draft",
  "isPublic": false,
  "publishedAt": null,
  "archivedAt": null,
  "createdAt": "2026-08-16T18:00:00.000Z"
}
```

| Поле          | Описание                                                            |
| ------------- | ------------------------------------------------------------------- |
| `title`       | Название формы, до 500 символов                                     |
| `schema`      | Страницы и поля формы — см. [раздел 12](#12-схема-формы)            |
| `settings`    | Произвольные настройки клиента, сервер их не интерпретирует         |
| `status`      | Текущее состояние: `draft`, `scheduled`, `published` или `archived` |
| `isPublic`    | Открыта ли форма всем прямо сейчас                                  |
| `publishedAt` | Момент публикации, `null` у черновика                               |
| `archivedAt`  | Момент архивации, `null` у неархивной формы                         |

**Статус не хранится отдельным полем — он вычисляется** из двух дат на момент
запроса:

| Значение    | Условие                                  |
| ----------- | ---------------------------------------- |
| `archived`  | Дата архивации задана и уже наступила    |
| `draft`     | Даты публикации нет                      |
| `published` | Дата публикации наступила                |
| `scheduled` | Дата публикации задана, но ещё в будущем |

Порядок проверок важен: архивация перекрывает всё остальное, поэтому архивная
форма непублична, даже если когда-то была опубликована. Публичной формой
считается та, у которой `status` равен `published`; именно для неё `isPublic`
становится `true`.

Обе даты меняются только переходами жизненного цикла, и у каждого перехода есть
обратный:

```
        публикация {date}         архивация {date}
draft ────────────────────► published ──────────────────► archived
  ▲     ◄────────────────      │  ▲   ◄─────────────────    │
  │      снятие с публикации   │  │    возврат из архива    │
  │                            │  └─────────────────────────┘
  │  публикация датой в будущем│      архивация и возврат
  └────────── scheduled ◄──────┘      работают из любого статуса
        снятие с публикации
```

`scheduled` — это та же публикация, просто дата ещё не наступила; отдельного
перехода в это состояние нет. Так же и архивация датой в будущем: до
наступления даты форма живёт обычной жизнью.

### 10.5. Ответ на форму (FormResponse)

```json
{
  "id": "b7a3c2d1-8e4f-4a5b-9c6d-7e8f9a0b1c2d",
  "formId": "3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b",
  "answers": { "full_name": "Иван Иванов", "age": 27, "topics": ["backend"] },
  "metadata": { "userAgent": "Mozilla/5.0", "locale": "ru-RU" },
  "submittedAt": "2026-08-16T18:30:00.000Z",
  "createdAt": "2026-08-16T18:29:41.000Z",
  "updatedAt": "2026-08-16T18:30:00.000Z"
}
```

`answers` — плоский словарь: ключ совпадает с именем поля в схеме формы,
значение может быть строкой, числом, логическим значением или массивом строк.

`metadata` — место для служебных данных клиента: язык интерфейса, источник
перехода, версия приложения. Содержимое произвольное.

`submittedAt` отличает черновик от отправленного ответа. Из тела запроса это
поле не принимается: его проставляет сервер, и только в ответ на
`POST /api/forms/:formId/responses/:id/submit`. От него же зависит, кто сможет
открыть ответ дальше (см. [раздел 5](#5-права-доступа)).

### 10.6. Фоновая задача (Job)

```json
{
  "id": "d4e5f6a7-b8c9-4d0e-9f1a-2b3c4d5e6f70",
  "type": "form-responses.export",
  "status": "succeeded",
  "progress": 100,
  "processedCount": 1348,
  "totalCount": 1348,
  "result": {
    "file": {
      "name": "export-2026-08-16.xlsx",
      "size": 184320,
      "mimeType": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"
    },
    "rowCount": 1348
  },
  "error": null,
  "createdAt": "2026-08-16T18:40:00.000Z",
  "startedAt": "2026-08-16T18:40:01.000Z",
  "finishedAt": "2026-08-16T18:40:12.000Z"
}
```

Состояния задачи:

| Статус      | Что значит                            | Конечное |
| ----------- | ------------------------------------- | -------- |
| `pending`   | Принята и ждёт свободного обработчика | нет      |
| `running`   | Выполняется                           | нет      |
| `succeeded` | Готово, результат в `result`          | да       |
| `failed`    | Не получилось, причина в `error`      | да       |
| `cancelled` | Отменена до или во время выполнения   | да       |

Поле `progress` — процент готовности:

- `100` — только когда задача действительно завершилась успехом;
- `null` — пока неизвестен общий объём работы;
- в остальных случаях — доля обработанного, но не больше `99`. Так сделано
  намеренно: пока файл не готов, прогресс не покажет сотню.

Ошибка задачи приходит парой «код — сообщение»:

```json
{
  "code": "EXPORT_TOO_LARGE",
  "message": "Large exports are not supported yet: 800000 rows"
}
```

| Код                | Причина                                                 |
| ------------------ | ------------------------------------------------------- |
| `INVALID_PAYLOAD`  | Задача создана с некорректными параметрами              |
| `UNKNOWN_JOB_TYPE` | Для такого типа операции нет обработчика                |
| `ENQUEUE_FAILED`   | Не удалось поставить задачу в очередь                   |
| `FORM_NOT_FOUND`   | Форму удалили между постановкой задачи и её выполнением |
| `EXPORT_TOO_LARGE` | Ответов больше, чем выдерживает текущая выгрузка        |
| `INTERNAL_ERROR`   | Непредвиденный сбой обработчика                         |

## 11. Справочник методов

### Служебные методы (System)

---

#### `GET /health` — проверка живости

Отвечает `{ "status": "ok" }`, если процесс поднят. Подходит для проверки
контейнера балансировщиком и для healthcheck в оркестраторе.

К базе и очереди не обращается, поэтому успешный ответ не гарантирует, что
зависимости живы.

Токен не нужен, параметров нет.

```http
GET /health HTTP/1.1
Host: localhost:3000
```

---

### Вход и профиль (Auth)

---

#### `POST /api/auth/login` — вход по email и паролю

Обменивает учётные данные на токен со сроком жизни 24 часа. Достаточно вызвать
один раз и переиспользовать полученный токен, пока не истечёт `expiresAt`.

**Доступ.** Открыт всем. Ограничение частоты — 5 попыток в минуту с одного
адреса.

**Тело запроса**

| Поле       | Тип    | Обязательное | Правила                            |
| ---------- | ------ | ------------ | ---------------------------------- |
| `email`    | строка | да           | Корректный адрес, регистр не важен |
| `password` | строка | да           | Не может быть пустым               |

```http
POST /api/auth/login HTTP/1.1
Host: localhost:3000
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "password"
}
```

**Ответ `200`**

```json
{
  "id": "0f0e3a35-9a8a-4d21-9b6a-9f7f1c0b3a10",
  "name": "Session Token (16.08.2026)",
  "expiresAt": "2026-08-17T18:00:00.000Z",
  "createdAt": "2026-08-16T18:00:00.000Z",
  "token": "vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q"
}
```

Сохраните `token` сразу — повторно он не выдаётся.

**Возможные ошибки**

| Код | Причина                                       |
| --- | --------------------------------------------- |
| 400 | Неверный формат email или пустой пароль       |
| 401 | Неверная пара email и пароль                  |
| 429 | Больше пяти попыток за минуту с одного адреса |

Несуществующий адрес и неверный пароль отвечают одинаково, поэтому подобрать
существующие учётные записи через этот метод нельзя.

---

#### `GET /api/auth/me` — профиль текущего пользователя

Возвращает владельца предъявленного токена. Удобно вызывать на старте
приложения: сразу проверяет, что токен жив, и отдаёт идентификатор для
локального состояния.

**Доступ.** Нужен действующий токен.

```http
GET /api/auth/me HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
```

**Ответ `200`**

```json
{
  "id": "8f14e45f-ceea-467a-9c31-2b1b5f9dfc02",
  "email": "user@example.com",
  "createdAt": "2026-07-25T10:02:25.000Z"
}
```

**Возможные ошибки**

| Код | Причина                                                    |
| --- | ---------------------------------------------------------- |
| 401 | Токена нет, он испорчен, просрочен или пользователь удалён |

### API-токены (API tokens)

Все методы группы требуют токен — анонимного доступа здесь нет ни к одному.

---

#### `GET /api/tokens` — список токенов

Отдаёт ваши персональные токены: то, что видит пользователь на экране «Ключи
API». Сессионные токены, полученные входом по паролю, в список не попадают —
ими не управляют, они истекают сами.

**Доступ.** Нужен действующий токен. Чужие ключи в выдачу не попадают.

**Параметры запроса**

| Параметр | Тип   | По умолчанию | Описание        |
| -------- | ----- | ------------ | --------------- |
| `page`   | целое | `1`          | Номер страницы  |
| `limit`  | целое | `20`         | Размер страницы |

```http
GET /api/tokens?page=1&limit=20 HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
```

**Ответ `200`**

```json
{
  "data": [
    {
      "id": "0f0e3a35-9a8a-4d21-9b6a-9f7f1c0b3a10",
      "name": "CI pipeline",
      "expiresAt": null,
      "createdAt": "2026-08-16T18:00:00.000Z"
    }
  ],
  "meta": { "total": 1, "page": 1, "limit": 20, "totalPages": 1 }
}
```

Самих секретов здесь нет: токен показывается только в момент выпуска.

**Возможные ошибки**

| Код | Причина                         |
| --- | ------------------------------- |
| 400 | Некорректные `page` или `limit` |
| 401 | Нет действующего токена         |

---

#### `POST /api/tokens` — выпустить токен

Создаёт долгоживущий ключ для интеграций, CI и серверных скриптов — всего, что
не может входить по паролю.

**Доступ.** Нужен действующий токен. Новый ключ достаётся его владельцу.

**Тело запроса**

| Поле        | Тип             | Обязательное | Правила                  |
| ----------- | --------------- | ------------ | ------------------------ |
| `name`      | строка          | да           | От 1 до 100 символов     |
| `expiresAt` | дата или `null` | нет          | Без даты токен бессрочен |

```http
POST /api/tokens HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
Content-Type: application/json

{
  "name": "CI pipeline"
}
```

**Ответ `201`**

```json
{
  "id": "1a2b3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
  "name": "CI pipeline",
  "expiresAt": null,
  "createdAt": "2026-08-16T18:05:00.000Z",
  "token": "aB3dE6gH9jK2mN5pQ8sT1vW4xY7zA0cD3fG6hJ9kL2m"
}
```

**Возможные ошибки**

| Код | Причина                                                     |
| --- | ----------------------------------------------------------- |
| 400 | Нет имени, оно пустое или длиннее 100 символов; пустое тело |
| 400 | `expiresAt` не похож на дату                                |
| 401 | Нет действующего токена                                     |

---

#### `DELETE /api/tokens/:id` — отозвать токен

Удаляет ключ безвозвратно. Пригодится при ротации, компрометации и для выхода
из системы — если удалить собственный сессионный токен, следующий запрос с ним
получит `401`.

**Доступ.** Только владелец токена.

**Параметры пути**

| Параметр | Тип  | Описание             |
| -------- | ---- | -------------------- |
| `id`     | UUID | Идентификатор токена |

```http
DELETE /api/tokens/1a2b3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
```

**Ответ `204`** — тело пустое.

**Возможные ошибки**

| Код | Причина                                |
| --- | -------------------------------------- |
| 401 | Нет действующего токена                |
| 403 | Токен принадлежит другому пользователю |
| 404 | Токена с таким идентификатором нет     |

### Формы (Forms)

---

#### `GET /api/forms` — список ваших форм

Главный экран конструктора: поиск по названию, вкладки «Черновики»,
«Опубликованные», «Архив».

**Доступ.** Нужен действующий токен. Метод отдаёт только ваши формы — даже
чужие опубликованные сюда не попадут, их можно открыть только поштучно по
идентификатору.

**Параметры запроса**

| Параметр      | Тип    | По умолчанию | Описание                                         |

| `page`        | целое  | `1`          | Номер страницы                                   |


**Ответ `200`**

**Возможные ошибки**

#### `GET /api/forms/:id` — получить форму со схемой

Единственный метод, который отдаёт содержимое формы анониму. Им пользуются и
редактор владельца, и страница заполнения у респондента.

**Доступ.** Токен не обязателен, но если заголовок передан, он должен быть
валидным.

| Кто                 | Форма опубликована | Черновик, план или архив |
| ------------------- | ------------------ | ------------------------ |
| Аноним              | 200                | 401                      |
| Владелец            | 200                | 200                      |
| Другой пользователь | 200                | 403                      |

**Параметры пути**

| Параметр | Тип  | Описание            |
| -------- | ---- | ------------------- |
| `id`     | UUID | Идентификатор формы |

```http
GET /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b HTTP/1.1

```

**Возможные ошибки**

| --- | ----------------------------------------------------- |

[Жизненный цикл формы](#жизненный-цикл-формы-lifecycle).

#### `POST /api/forms` — создать форму

### Жизненный цикл формы (Lifecycle)

Четыре перехода управляют двумя датами — публикации и архивации. Статус формы
из них вычисляется, отдельного поля под него нет.

| Метод                 | Что делает              |
| --------------------- | ----------------------- |
| `POST /:id/publish`   | Ставит дату публикации  |
| `POST /:id/unpublish` | Убирает дату публикации |
| `POST /:id/archive`   | Ставит дату архивации   |
| `POST /:id/unarchive` | Убирает дату архивации  |

Общее для всех четырёх:

- **доступ** — только владелец формы, отдельной роли для публикации нет;
- **ответ `200`** — форма целиком в новом состоянии;
- **ошибки** — `400` на недопустимый переход, `401` без токена, `403` на чужую
  форму, `404`, если формы нет.

Публикация и архивация принимают необязательное тело с моментом перехода:

```json
{ "date": "2026-09-01T09:00:00Z" }
```

Без тела переход происходит сразу. Дата в будущем откладывает его: форма
получает статус `scheduled` или ждёт запланированной архивации. Снятие с
публикации и возврат из архива тела не принимают.

---

#### `POST /api/forms/:id/publish` — опубликовать

Открывает форму всем: с этого момента её схему может получить любой, а
респонденты могут отправлять ответы. Дата в будущем превращает вызов в
отложенную публикацию.

**Допустимые переходы**

| Текущий статус | Что произойдёт                                        |
| -------------- | ----------------------------------------------------- |
| `draft`        | Станет `published`, а с датой в будущем — `scheduled` |
| `scheduled`    | Дата публикации заменится на новую                    |
| `published`    | `400` — сначала снимите с публикации                  |
| `archived`     | `400` — сначала верните из архива                     |

```http
POST /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/publish HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
Content-Type: application/json

{ "date": "2026-09-01T09:00:00Z" }
```

**Ответ `200`**

```json
{
  "id": "3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b",
  "userId": "9f1c2d3e-4a5b-4c6d-8e9f-0a1b2c3d4e5f",
  "title": "Анкета участника",
  "schema": { "pages": [{ "name": "page_1", "elements": [] }] },
  "settings": {},
  "status": "scheduled",
  "isPublic": false,
  "publishedAt": "2026-09-01T09:00:00.000Z",
  "archivedAt": null,
  "createdAt": "2026-08-16T18:03:11.004Z"
}
```

Без тела получите то же самое, но со статусом `published`, флагом
`isPublic: true` и датой публикации, равной моменту вызова.

Отказ в переходе выглядит так:

```json
{
  "code": "BAD_REQUEST",
  "message": "Опубликовать можно только черновик или запланированную форму"
}
```

---

#### `POST /api/forms/:id/unpublish` — снять с публикации

Возвращает форму в черновики: публичный доступ закрывается, приём новых ответов
прекращается. Тем же вызовом отменяется запланированная публикация.

**Допустимые переходы**

| Текущий статус | Что произойдёт                    |
| -------------- | --------------------------------- |
| `published`    | Станет `draft`                    |
| `scheduled`    | Станет `draft`, план отменён      |
| `draft`        | `400` — снимать нечего            |
| `archived`     | `400` — сначала верните из архива |

```http
POST /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/unpublish HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
```

**Ответ `200`** — форма со статусом `draft` и `publishedAt: null`.

Собранные ответы никуда не денутся. Но респондент, не успевший дозаполнить
черновик, потеряет к нему доступ до следующей публикации: доступ к ответам
следует за доступом к форме.

---

#### `POST /api/forms/:id/archive` — архивировать

Закрывает опрос, сохраняя все данные. Форма перестаёт быть публичной, анонимы
больше не могут ни открыть её, ни отправить ответ. Владелец продолжает видеть
и форму, и ответы, и может выгружать их.

Дата в будущем откладывает архивацию: до её наступления ничего не меняется.

**Допустимые переходы**

| Текущий статус                       | Что произойдёт                                   |
| ------------------------------------ | ------------------------------------------------ |
| `draft`, `scheduled` или `published` | Станет `archived`, с датой в будущем — отложенно |
| `archived`                           | `400` — форма уже в архиве                       |

```http
POST /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/archive HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
```

**Ответ `200`** — форма со статусом `archived` и `isPublic: false`. Дата
публикации при этом сохраняется, поэтому возврат из архива вернёт форму ровно в
то состояние, в котором её закрыли.

---

#### `POST /api/forms/:id/unarchive` — вернуть из архива

Убирает дату архивации. Пригодится, если опрос решили продлить или
заархивировали по ошибке; тем же вызовом отменяется запланированная архивация.

**Допустимые переходы**

| Состояние               | Что произойдёт                                      |
| ----------------------- | --------------------------------------------------- |
| Форма в архиве          | Статус вернётся к тому, что диктует дата публикации |
| Архивация запланирована | План отменён                                        |
| Форма не в архиве       | `400` — возвращать нечего                           |

```http
POST /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/unarchive HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
```

**Ответ `200`** — форма с `archivedAt: null`. Если её архивировали
опубликованной, она снова станет публичной.

---

### Ответы на формы (Form responses)

Ответы — вложенный ресурс формы, поэтому все адреса начинаются с
`/api/forms/:formId/responses`.

Сводный список требует токен и отдаёт только ответы ваших форм. Работа с
одним ответом устроена мягче: пока он не отправлен, его открывает любой, у кого
есть ссылка. Подробнее — в разделе [Права доступа](#5-права-доступа).

Заполнение разведено на два шага: `POST` и `PATCH` сохраняют черновик, а
отправляет его отдельный `POST .../submit`. Черновик сохраняется недозаполненным
— незаполненные обязательные поля становятся ошибкой только при отправке.

---

#### `GET /api/forms/:formId/responses` — список ответов

Таблица ответов в интерфейсе автора формы: постранично, с поиском по значениям
ответов и отбором отправленных.

**Доступ.** Только автор формы. Чужая и несуществующая форма отвечают одинаково
— пустой страницей со `total: 0`, так что по ответу нельзя узнать, существует ли
форма.

**Параметры пути**

| Параметр | Тип  | Описание            |
| -------- | ---- | ------------------- |
| `formId` | UUID | Идентификатор формы |

**Параметры запроса**

| Параметр         | Тип                 | По умолчанию | Описание                                  |
| ---------------- | ------------------- | ------------ | ----------------------------------------- |
| `page`           | целое               | `1`          | Номер страницы                            |
| `limit`          | целое               | `20`         | Размер страницы, максимум 100             |
| `answer[<поле>]` | строка              | —            | Поиск подстроки в ответе на это поле      |
| `answered`       | имя поля или массив | —            | Заполнены все перечисленные поля          |
| `submitted`      | `true`              | —            | Только отправленные ответы                |
| `submittedFrom`  | дата                | —            | Отправленные не раньше указанного момента |
| `submittedTo`    | дата                | —            | Отправленные не позже указанного момента  |
| `formId`         | UUID                | —            | Дополнительное сужение по форме           |

```http
GET /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/responses?submitted=true&answer[full_name]=Иван HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
```

**Ответ `200`**

```json
{
  "data": [
    {
      "id": "b7a3c2d1-8e4f-4a5b-9c6d-7e8f9a0b1c2d",
      "formId": "3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b",
      "answers": {
        "full_name": "Иван Иванов",
        "age": 27,
        "topics": ["backend"]
      },
      "metadata": {},
      "submittedAt": "2026-08-16T18:30:00.000Z",
      "createdAt": "2026-08-16T18:29:41.000Z",
      "updatedAt": "2026-08-16T18:30:00.000Z"
    }
  ],
  "meta": { "total": 1, "page": 1, "limit": 20, "totalPages": 1 }
}
```

**Возможные ошибки**

| Код | Причина                        |
| --- | ------------------------------ |
| 400 | Некорректные параметры запроса |
| 401 | Нет действующего токена        |

---

#### `GET /api/forms/:formId/responses/:id` — получить один ответ

Двумя словами: черновик открывает любой, у кого есть ссылка, а отправленный
ответ — только автор формы.

**Доступ.**

| Состояние ответа               | Кому доступен                  |
| ------------------------------ | ------------------------------ |
| Черновик (`submittedAt: null`) | Всем, кому доступна сама форма |
| Отправленный                   | Только автору формы            |

**Параметры пути**

| Параметр | Тип  | Описание             |
| -------- | ---- | -------------------- |
| `formId` | UUID | Идентификатор формы  |
| `id`     | UUID | Идентификатор ответа |

```http
GET /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/responses/b7a3c2d1-8e4f-4a5b-9c6d-7e8f9a0b1c2d HTTP/1.1
Host: localhost:3000
```

**Ответ `200`** — объект ответа, см. раздел 10.5.

**Возможные ошибки**

| Код | Причина                                             |
| --- | --------------------------------------------------- |
| 401 | Доступа нет, запрос анонимный                       |
| 403 | Доступа нет, токен принадлежит другому пользователю |
| 404 | Ответа нет либо он относится к другой форме         |
| 429 | Исчерпан лимит на заполнение формы                  |

---

#### `POST /api/forms/:formId/responses` — начать заполнение

Точка входа публичного сценария: респондент открыл форму и сохраняет первые
ответы. Созданный ответ всегда черновик — `submittedAt` у него `null`, и из
тела запроса это поле не принимается.

**Доступ.** Токен не обязателен. В опубликованную форму ответ примут от кого
угодно; в закрытую — только от её автора, и тогда токен нужен.

**Тело запроса**

| Поле       | Тип    | Обязательное | Правила                                                                          |
| ---------- | ------ | ------------ | -------------------------------------------------------------------------------- |
| `answers`  | объект | да           | Ключ — имя поля схемы, значение — строка, число, `true`/`false` или массив строк |
| `metadata` | объект | нет          | Произвольные данные клиента, по умолчанию пустой объект                          |

`answers` может быть пустым объектом: черновик на то и черновик.

Ответы проверяются дважды: сначала на формальную корректность, затем на
соответствие схеме формы. Черновику вторая проверка достаётся урезанной —
пропускается всё, что нарушает любое незаконченное значение:

| Что проверяется                                    | У каких полей                         | В черновике |
| -------------------------------------------------- | ------------------------------------- | ----------- |
| Тип значения: строка, конечное число, массив строк | у всех                                | да          |
| Верхняя граница: `maxLength`, `max`                | `text`, `email`, `textarea`, `number` | да          |
| Значение из списка вариантов                       | `dropdown`, `radiogroup`, `checkbox`  | да          |
| Лишних полей в ответе нет                          | у всех                                | да          |
| Обязательное поле заполнено                        | у всех                                | нет         |
| Нижняя граница: `minLength`, `min`                 | `text`, `email`, `textarea`, `number` | нет         |
| Формат адреса                                      | `email`                               | нет         |

Смысл деления простой: недописанное значение неизбежно нарушает нижнюю границу
и формат, а верхнюю границу и тип — нет. Эссе на 25 000 символов при
`minLength: 30000` сохранится, `iva` в поле почты — тоже, а строка вместо числа
или лишнее поле не сохранятся никогда.

Пустая строка и пустой список считаются отсутствием ответа, а не ответом.
Поэтому очищенное поле не спорит со своим типом при автосохранении и не
закрывает обязательное поле при отправке.

```http
POST /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/responses HTTP/1.1
Host: localhost:3000
Content-Type: application/json

{
  "answers": {
    "full_name": "Иван Иванов"
  },
  "metadata": { "locale": "ru-RU" }
}
```

**Ответ `201`** — сохранённый черновик.

**Возможные ошибки**

| Код | Причина                                                             |
| --- | ------------------------------------------------------------------- |
| 400 | Нарушен формат тела; пустое тело; ответы не сошлись со схемой формы |
| 401 | Форма закрыта или не существует, а запрос анонимный                 |
| 403 | Форма закрыта или не существует, токен чужой                        |
| 429 | Исчерпан лимит на заполнение формы                                  |

Несуществующая форма неотличима от закрытой: проверка доступа идёт первой,
поэтому вы получите `401` или `403`, а не `404`.

Так выглядит несовпадение со схемой:

```json
{
  "code": "BAD_REQUEST",
  "message": "Validation failed",
  "details": [
    { "field": "full_name", "message": "This field is required" },
    { "field": "age", "message": "Answer must be at least 14" }
  ]
}
```

#### `PATCH /api/forms/:formId/responses/:id` — изменить ответ

Этим методом фронтенд автосохраняет черновик по мере заполнения. Отправить
ответ отсюда нельзя — для этого есть `POST .../submit`.

Обновляются только переданные поля. Если `answers` не передавать, со схемой
формы сверятся уже сохранённые ответы.

Черновик проверяется мягко, по правилам `POST` выше. Если же правится уже
отправленный ответ (а это доступно только автору формы), проверка полная — он
не должен перестать быть валидным.

**Доступ.** Как и при чтении: черновик правит любой, у кого есть ссылка,
отправленный ответ — только автор формы.

**Тело запроса** — любое подмножество полей `answers` и `metadata`.

```http
PATCH /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/responses/b7a3c2d1-8e4f-4a5b-9c6d-7e8f9a0b1c2d HTTP/1.1
Host: localhost:3000
Content-Type: application/json

{
  "answers": { "full_name": "Иван Петров", "age": 28, "topics": ["backend"] }
}
```

**Ответ `200`** — ответ после изменения; поле `updatedAt` обновляется само.

**Возможные ошибки**

| Код | Причина                                                             |
| --- | ------------------------------------------------------------------- |
| 400 | Нарушен формат тела; пустое тело; ответы не сошлись со схемой формы |
| 401 | Доступа нет, запрос анонимный                                       |
| 403 | Доступа нет, токен принадлежит другому пользователю                 |
| 404 | Ответа нет либо он относится к другой форме                         |
| 429 | Исчерпан лимит на заполнение формы                                  |

---

#### `POST /api/forms/:formId/responses/:id/submit` — отправить ответ

Завершение публичного сценария: сохранённый черновик проверяется целиком и
получает `submittedAt`. Тело не нужно — отправляются те ответы, что уже
сохранены, дату проставляет сервер.

**Доступ.** Тот же, что у `PATCH`: пока ответ черновик, отправить его может
любой, у кого есть ссылка. Отправка необратима — после неё ответ виден только
автору формы, и повторный вызов вернёт `400`.

Своего лимита частоты у отправки нет — она случается один раз за заполнение,
поэтому под неё хватает общих 600 запросов в минуту.

**Параметры пути**

| Параметр | Тип  | Описание             |
| -------- | ---- | -------------------- |
| `formId` | UUID | Идентификатор формы  |
| `id`     | UUID | Идентификатор ответа |

Здесь и только здесь схема формы проверяется полностью: незаполненные
обязательные поля, нижние границы длины и чисел, формат адреса. Черновик при
неудаче остаётся нетронутым — исправьте ответы через `PATCH` и повторите
отправку.

```http
POST /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/responses/b7a3c2d1-8e4f-4a5b-9c6d-7e8f9a0b1c2d/submit HTTP/1.1
Host: localhost:3000
```

**Ответ `200`** — отправленный ответ с заполненным `submittedAt`.

**Возможные ошибки**

| Код | Причина                                                    |
| --- | ---------------------------------------------------------- |
| 400 | Ответы не сошлись со схемой формы; ответ уже был отправлен |
| 401 | Доступа нет, запрос анонимный                              |
| 403 | Доступа нет, токен принадлежит другому пользователю        |
| 404 | Ответа нет либо он относится к другой форме                |

Незаполненные обязательные поля выглядят так:

```json
{
  "code": "BAD_REQUEST",
  "message": "Validation failed",
  "details": [
    {
      "field": "full_name",
      "code": "REQUIRED",
      "message": "This field is required"
    }
  ]
}
```

### ИИ-помощник (AI)

Помощник собирает схему формы по описанию на естественном языке. Обращения к
модели ограничены суточной квотой на пользователя — по умолчанию 20 генераций,
счётчик обнуляется в полночь.

---

#### `POST /api/forms/:formId/ai/generate` — сгенерировать схему

Принимает текстовое описание и возвращает готовую схему. Текущая схема формы
отправляется модели вместе с запросом, поэтому метод одинаково хорош и для
создания формы с нуля, и для правки существующей: «добавь поле с телефоном»,
«сделай email обязательным».

**Результат никуда не сохраняется** — вы получаете схему и решаете, применять
ли её. Чтобы применить, отправьте её в `PATCH /api/forms/:id`.

**Доступ.** Только владелец формы.

**Тело запроса**

| Поле     | Тип    | Обязательное | Правила               |
| -------- | ------ | ------------ | --------------------- |
| `prompt` | строка | да           | От 1 до 5000 символов |

```http
POST /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/ai/generate HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
Content-Type: application/json

{
  "prompt": "Анкета участника конференции: имя, email, выбор трека, согласие на рассылку"
}
```

**Ответ `200`**

```json
{
  "status": "ok",
  "message": "Добавил четыре поля: имя, email, выбор трека и чекбокс согласия.",
  "schema": {
    "pages": [
      {
        "name": "page_1",
        "title": "Участник",
        "elements": [
          {
            "name": "full_name",
            "label": "Как вас зовут?",
            "type": "text",
            "required": true
          },
          {
            "name": "email",
            "label": "Email",
            "type": "email",
            "required": true
          }
        ]
      }
    ]
  }
}
```

| Поле      | Описание                                                                                      |
| --------- | --------------------------------------------------------------------------------------------- |
| `status`  | `ok` — схема готова; `unsupported` — такое схемой не выразить; `ambiguous` — запрос непонятен |
| `message` | Текст для показа пользователю: что сделано или чего не хватило                                |
| `schema`  | Схема при `status: "ok"`, иначе `null`                                                        |

Схема проходит те же проверки, что и при создании формы, поэтому её можно
отправлять на сохранение как есть.

**Возможные ошибки**

| Код | Причина                                        |
| --- | ---------------------------------------------- |
| 400 | Описание пустое или длиннее 5000 символов      |
| 401 | Нет действующего токена                        |
| 403 | Форма принадлежит другому пользователю         |
| 404 | Формы не существует                            |
| 429 | Исчерпана суточная квота                       |
| 503 | Модель недоступна или вернула нечитаемый ответ |

Квота списывается только за удачные генерации — неудачное обращение к модели её
не тратит. Ответ может прийти не сразу: при перегрузке провайдера запрос
повторяется дважды, а общий тайм-аут по умолчанию — 60 секунд.

Так выглядит исчерпанная квота:

```json
{
  "code": "TOO_MANY_REQUESTS",
  "message": "Суточный лимит запросов к ИИ исчерпан",
  "details": { "limit": 20, "resetAt": "2026-08-21T00:00:00.000Z" }
}
```

А так — недоступная модель. Подробности сбоя остаются в логах сервера:

```json
{
  "code": "SERVICE_UNAVAILABLE",
  "message": "AI-сервис временно недоступен"
}
```

### Экспорт ответов (Export)

---

#### `POST /api/forms/:formId/responses/export` — выгрузить ответы в XLSX

Ставит выгрузку в очередь и сразу возвращает задачу — файл готовится в фоне.
Сценарий целиком:

```
POST /api/forms/{formId}/responses/export   → 202, задача принята
GET  /api/jobs/{id}                         → опрашиваем, пока status не станет succeeded
GET  /api/jobs/{id}/download                → забираем .xlsx
```

**Доступ.** Только владелец формы — даже если форма опубликована, выгружать
ответы может лишь автор.

**Параметры пути**

| Параметр | Тип  | Описание            |
| -------- | ---- | ------------------- |
| `formId` | UUID | Идентификатор формы |

**Заголовки**

| Заголовок         | Обязательный | Описание                                                                 |
| ----------------- | ------------ | ------------------------------------------------------------------------ |
| `Authorization`   | да           | `Bearer <token>`                                                         |
| `Idempotency-Key` | нет          | Повторный запрос с тем же ключом вернёт ту же задачу, а не создаст новую |

Ключ идемпотентности стоит передавать всегда, когда кнопку «Экспорт» может
случайно нажать дважды: без него каждый вызов создаёт новую задачу. Ключ
действует в пределах вашего аккаунта.

Тело запроса не требуется.

```http
POST /api/forms/3c1a7b1e-4f2d-4e8a-9c1b-0a2d3e4f5a6b/responses/export HTTP/1.1
Host: localhost:3000
Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
Idempotency-Key: export-2026-08-16-a1
```

**Ответ `202`**

```json
{
  "id": "d4e5f6a7-b8c9-4d0e-9f1a-2b3c4d5e6f70",
  "type": "form-responses.export",
  "status": "pending",
  "progress": null,
  "processedCount": 0,
  "totalCount": null,
  "result": null,
  "error": null,
  "createdAt": "2026-08-16T18:40:00.000Z",
  "startedAt": null,
  "finishedAt": null
}
```

**Что попадёт в файл.** Один лист, первые три колонки — идентификатор ответа,
дата создания и дата отправки, дальше по колонке на каждое поле формы с
заголовком из его подписи.

**Возможные ошибки**

| Код | Причина                                |
| --- | -------------------------------------- |
| 401 | Нет действующего токена                |
| 403 | Форма принадлежит другому пользователю |
| 404 | Формы не существует                    |
| 429 | Больше десяти выгрузок за минуту       |
| 503 | Очередь фоновых задач недоступна       |

Часть ограничений проявляется уже после постановки — задача завершится статусом
`failed` с понятным кодом: `EXPORT_TOO_LARGE`, если ответов больше 500 000, и
`FORM_NOT_FOUND`, если форму удалили, пока задача ждала очереди.

### Фоновые задачи (Jobs)

Единый интерфейс ко всем долгим операциям. Создать задачу напрямую нельзя —
они появляются, когда вы запускаете экспорт.

#### `GET /api/jobs` — список задач

Центр уведомлений «Мои выгрузки»: что запущено, что готово, что упало. Удобно

**Доступ.** Нужен действующий токен, в выдачу попадают только ваши задачи.

#### `GET /api/jobs/:id/download` — скачать результат

Отдаёт готовый файл. Вызывайте, когда задача перешла в `succeeded` и в её
`result` появился объект `file`.

**Доступ.** Только владелец задачи.

```http
GET /api/jobs/d4e5f6a7-b8c9-4d0e-9f1a-2b3c4d5e6f70/download HTTP/1.1

Authorization: Bearer vJ8kQ2mZ5nR7pT1wY4xA6bC9dE0fG3hJ5kL8mN1oP4q
```

**Ответ `200`** — бинарный поток:

```http
HTTP/1.1 200 OK
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Length: 184320
Content-Disposition: attachment; filename="export-2026-08-16.xlsx"
```

Имя файла — `export-<YYYY-MM-DD>.xlsx`, где дата равна дню выполнения задачи. То же имя лежит
в `result.file.name` задачи.

**Скачивать нужно запросом с заголовком авторизации** — просто подставить ссылку
в `<a href>` или `window.open` не выйдет. Загрузите файл через `fetch` и
отдайте пользователю как `Blob`.

**Возможные ошибки**

| Код | Причина                                                  |
| --- | -------------------------------------------------------- |
| 400 | Задача ещё не завершилась успехом                        |
| 401 | Нет действующего токена                                  |
| 403 | Задача принадлежит другому пользователю                  |
| 404 | Задачи нет, у неё нет файла или файл пропал из хранилища |

Если соединение оборвётся уже после отправки заголовков, вы получите обрезанный
файл без JSON-ответа об ошибке — такую загрузку нужно повторить.

## 12. Схема формы

Схема описывает, что увидит респондент: страницы, поля на них и правила
проверки. Хранится в поле `schema` формы.

```
Схема
└── pages — страницы, минимум одна
    ├── name       техническое имя страницы
    ├── title      заголовок для респондента
    ├── visibleIf  условие показа страницы
    └── elements   поля страницы
```

### Поля страницы

Общие свойства есть у любого поля:

| Свойство      | Тип        | Обязательное | Правила                                                        |
| ------------- | ---------- | ------------ | -------------------------------------------------------------- |
| `name`        | строка     | да           | 1–100 символов, латиница, цифры, `-` и `_`, начинается с буквы |
| `label`       | строка     | да           | 1–500 символов, подпись для респондента                        |
| `type`        | строка     | да           | Тип поля, см. таблицу ниже                                     |
| `required`    | логическое | нет          | По умолчанию `false`                                           |
| `placeholder` | строка     | нет          | Подсказка внутри поля                                          |
| `visibleIf`   | условие    | нет          | Правило показа поля                                            |

**`name` — это ключ ответа.** Именно под ним значение попадёт в `answers`, по
нему же работает фильтр `answer[<поле>]`, поэтому имена стоит выбирать
осмысленно: `full_name`, а не `field_2`.

Доступные типы полей:

| Тип                         | Дополнительные свойства                    | Что придёт в ответе      |
| --------------------------- | ------------------------------------------ | ------------------------ |
| `text`, `email`, `textarea` | `validation: { minLength, maxLength }`     | строка                   |
| `number`                    | `validation: { min, max }`                 | число                    |
| `dropdown`, `radiogroup`    | `choices: [{ value, text }]`, минимум один | строка — одно из `value` |
| `checkbox`                  | `choices: [{ value, text }]`, минимум один | массив строк из `value`  |

У вариантов ответа `value` — то, что сохранится, а `text` — то, что увидит
респондент.

### Условия показа

Условие в `visibleIf` — это либо одно правило, либо композиция правил через
`and` и `or`. Вложенность не ограничена.

```json
{ "field": "age", "operator": "greaterThanOrEqual", "value": 18 }
```

```json
{
  "and": [
    { "field": "age", "operator": "greaterThanOrEqual", "value": 18 },
    {
      "or": [
        { "field": "topics", "operator": "contains", "value": "backend" },
        { "field": "topics", "operator": "contains", "value": "frontend" }
      ]
    }
  ]
}
```

| Свойство   | Описание                                                  |
| ---------- | --------------------------------------------------------- |
| `field`    | Имя поля, от которого зависит показ                       |
| `operator` | Оператор сравнения                                        |
| `value`    | Значение для сравнения; не нужно для `empty` и `notEmpty` |

Доступные операторы: `equals`, `notEquals`, `greaterThan`,
`greaterThanOrEqual`, `lessThan`, `lessThanOrEqual`, `contains`, `notContains`,
`empty`, `notEmpty`.

Условия хранятся вместе со схемой и отдаются клиенту как есть — показ и скрытие
полей вычисляет интерфейс формы.

### Пример целиком

```json
{
  "pages": [
    {
      "name": "page_1",
      "title": "О себе",
      "elements": [
        {
          "name": "full_name",
          "label": "Как вас зовут?",
          "type": "text",
          "required": true,
          "validation": { "minLength": 2, "maxLength": 100 }
        },
        {
          "name": "age",
          "label": "Сколько вам лет?",
          "type": "number",
          "validation": { "min": 14, "max": 120 }
        },
        {
          "name": "topics",
          "label": "Что вам интересно?",
          "type": "checkbox",
          "choices": [
            { "value": "backend", "text": "Backend" },
            { "value": "frontend", "text": "Frontend" }
          ]
        },
        {
          "name": "experience",
          "label": "Расскажите про опыт с backend",
          "type": "textarea",
          "visibleIf": {
            "field": "topics",
            "operator": "contains",
            "value": "backend"
          }
        }
      ]
    }
  ]
}
```
